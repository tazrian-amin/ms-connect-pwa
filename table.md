# PWA Feature Progress

Current implementation status based on the codebase review on 2026-09-09. Completion percentages are practical estimates of the feature's implementation maturity, not automated test coverage.

| Major Features | Complexity level | Complete in % | Comment | TODO |
| --- | --- | ---: | --- | --- |
| Home screen and device category discovery | Low | 90% | Lists all six device categories with icons, descriptions, search filtering, and links to device pages. | Add final UX polish, accessibility review, and coverage for empty and error states. |
| Device routes and connection workflow | Medium | 90% | Supports category routes, invalid-category handling, connection status, connect/disconnect actions, browser support warnings, and category validation. | Test reconnect and failure paths across supported browsers and improve recovery messaging. |
| Bluetooth/Web Bluetooth transport | High | 85% | Includes GATT connection, HM-10 UART discovery, notifications, chunked writes, disconnect handling, reconnect support, and mapped errors. | Harden transport against malformed packets, concurrent commands, timeouts, and long-running reconnect scenarios. |
| Six device-specific firmware integrations and dashboards | High | 25% | Shared Bluetooth transport and category routing are in place, but each device needs its own firmware contract, data model, command set, telemetry mapping, and dashboard. Dewater Pump Float is the most developed; the other five devices currently have placeholder or partially generic experiences. | Define and version the firmware contract for each device, implement device-specific parsers and commands, replace placeholder dashboards with production views, connect each dashboard to live data, and test every device independently against real hardware. |
| Device commands and provisioning | High | 80% | Supports JSON commands, command logs, configuration reads, reply matching and timeouts, first-time setup, identity editing, and MCU reset recovery. Some commands remain provisional. | Finalize provisional commands with firmware, validate every response shape, and complete end-to-end provisioning tests. |
| Device information and live readings | Medium | 85% | Displays device identity, category, serial and product information, connection time, and parsed firmware readings. | Define and handle all firmware payload variants, stale readings, missing fields, and device clock/session edge cases. |
| Telemetry history and charts | Medium | 85% | Retains bounded reading histories and provides responsive charts with downsampling, averages, units, fixed domains, threshold lines, and empty states. | Validate chart values against hardware readings, persist history if needed, and add loading, stale-data, and export behavior. |
| Dewater Pump Float monitoring dashboard | High | 80% | Provides six-pump monitoring, pump controls, operating modes, thresholds, counters, reset flows, setup/edit dialogs, and live state hydration. Some hardware/firmware behavior is still provisional. | Complete hardware validation, wire remaining firmware behavior, finalize command semantics, and test all six pumps and failure states. |
| Water level, discharge flow, and bin height devices | Medium | 65% | Generic live telemetry and bin visualization are present. Bin height still uses ADC-to-percentage display rather than calibrated physical capacity. | Connect each device to production payloads, calibrate bin height to physical units, and add device-specific thresholds and validation. |
| Conveyor Volumetric Scale dashboards | High | 45% | Includes locations, scale monitoring layouts, drag-and-drop ordering, editing dialogs, responsive behavior, and rate graphs. Visible dashboard data is currently demo-driven rather than connected to live scale telemetry. | Replace demo data with live scale telemetry, persist edits, implement production aggregation, and validate rate graphs and multi-location behavior. |
| Device configuration and settings | High | 55% | Pump-float configuration is substantially integrated. Volumetric configuration supports validated writes but is not mounted in the active page and does not read values back. Generic sample-period and command-console controls are mostly disabled in category pages. | Mount the missing controls, implement read-back and persistence, expose settings per device category, and test validation and rollback on write failures. |
| Offline telemetry persistence and cloud synchronization | High | 0% | No local database, offline telemetry queue, cloud storage integration, retry strategy, or conflict handling is implemented yet. | Decide the local storage technology, cloud data model and API, retention limits, authentication, queue format, retry/backoff rules, duplicate handling, conflict resolution, and behavior when storage is full or the device disconnects. Then implement and test the end-to-end sync flow. |
| PWA install, updates, and offline support | Medium | 80% | Includes manifest metadata, standalone mode, icons, service-worker registration, update notification, controlled activation, an offline fallback page, app-shell precaching, runtime navigation caching, and runtime caching for visited Next.js assets. This does not yet persist Bluetooth telemetry or upload it after connectivity returns. | Add browser-level offline/update tests, verify install behavior on target browsers, and consider build-time precaching for critical assets on first launch. |
